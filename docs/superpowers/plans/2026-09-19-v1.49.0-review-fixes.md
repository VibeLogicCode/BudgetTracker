**Goal:** Close all 60 findings in `docs/reviews/2026-09-19-v1.48.0-review.md` (sections A–F) in one release: the loan ledger's wrong-money defects, the security holes, the pre-existing data-loss paths, the measured performance waste, and the design critique's P0–P3 — including the two owner rulings (nav renamed to **"Loans & Coverage"**; the balance MetricCard deleted and **Owing today** made the loan page's single hero).

**Architecture:** One balance rule everywhere. `src/lib/loans/ledger.ts` gains a single period walk that both the truth path and the stored-replay path use, with payments capped at the running balance (the repo's existing MUST-11.14 semantics) and interest added at each period end. `recomputeBalance` interleaves posted interest with payments by date instead of front-loading it, so the stored column, the engine's posted balance and the row walk agree by construction. The anchor wall moves from `period_end` to `period_start`, so a statement supersedes every period that began before it. Reconcile becomes one transaction. Reads split into a cheap `listLoanRows` and a derived `listLoanSummaries`, and the loan page reads its facts once. Every loan-link write takes a viewer. The ledger card is rebuilt on the house grammar (StatTile, AmountCell, TableWrap responsive, INTEREST_WORDING) with the reconcile form inside it.

**Tech Stack:** Next.js 16 App Router, React 19, server actions, Drizzle over better-sqlite3, hand-written SQL migrations, Vitest + Testing Library (jsdom, no jest-dom), Tailwind v4 tokens in `src/app/globals.css`, node-cron.

**Spec:** `docs/reviews/2026-09-19-v1.48.0-review.md` — every task below cites its finding ids (A1…F7). The ledger design spec `docs/superpowers/specs/2026-09-18-loan-ledger-design.md` still governs anything this plan does not change; where they differ, this plan wins and Task 27 records the deviation in that spec's §16.

```ts
interface WalkPeriod { start: string; end: string; cycleDays: number; openingCents: number; inside: Movement[]; appliedCents: number; advancesCents: number; interestCents: number; closingCents: number; charge: PeriodCharge; rate: RateInForce | null }

/**
 * THE ONE BALANCE RULE. A payment applies at most what is owed at that moment (MUST-11.14, the
 * same cap applied_cents carries in the database); an advance adds in full; interest joins at the
 * period end. Truth and stored-replay differ ONLY in where the interest figure comes from, so they
 * cannot disagree about anything else -- and recomputeBalance in loans.ts walks the same events in
 * the same order with the same cap.
 */
function walkPeriods(input: LedgerInput, interestFor: (period: Omit<WalkPeriod, 'interestCents' | 'closingCents'>, index: number) => number): { closed: WalkPeriod[]; open: Omit<WalkPeriod, 'interestCents' | 'closingCents'> } {
  const closed: WalkPeriod[] = [];
  let balance = input.startBalanceCents;
  let index = 0;
  for (const boundary of periodBoundaries(input.startDate, input.postingDay, input.today)) {
    const cycleDays = daysBetweenIso(previousPostingDate(boundary.end, input.postingDay), boundary.end);
    const inside = inWindow(input.movements, boundary.start, boundary.end);
    const rate = rateOn(boundary.start, input.rateHistory);
    // Apply movements day by day so a payment is capped at what is owed THAT day.
    let running = balance; let applied = 0; let advances = 0;
    for (const m of [...inside].sort((a, b) => (a.date < b.date ? -1 : a.date > b.date ? 1 : 0))) {
      if (m.amountCents < 0) { const paid = Math.min(-m.amountCents, running); running -= paid; applied += paid; }
      else { running += m.amountCents; advances += m.amountCents; }
    }
    const charge = periodCharge({ start: boundary.start, end: boundary.end, cycleDays, openingCents: balance, principalCents: input.principalCents, movements: inside, rate });
    const partial = { start: boundary.start, end: boundary.end, cycleDays, openingCents: balance, inside, appliedCents: applied, advancesCents: advances, charge, rate };
    if (!boundary.closed) return { closed, open: partial };
    const interestCents = interestFor(partial, index++);
    const closingCents = running + interestCents; // running >= 0 by construction; interest >= 0 for postings
    closed.push({ ...partial, interestCents, closingCents: Math.max(0, closingCents) });
    balance = Math.max(0, closingCents);
  }
  throw new LedgerRangeError('walkPeriods found no open period');
}
```
